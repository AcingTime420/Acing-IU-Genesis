### Connected run and infrastructure

A new mode-0700 disposable PostgreSQL cluster was initialized specifically for this task. It bound only 127.0.0.1:55440 with Unix sockets disabled. Guarded connection environment used `genesis_authority_test`, synthetic role `authority_test`; no existing user database was contacted. Existing test schema-reset and advisory-lock guards were inspected before running. Local trust authentication is restricted to the disposable isolated cluster and is not a production recommendation.

Debug and Release suites ran sequentially with the PostgreSQL process in the same execution namespace. The disposable schema was then explicitly reset before the connected demonstration, migrated with `scripts/genesis-authority.py migrate`, and seeded with `fixtures`. The synthetic fixture file was mode 0600 outside all repository worktrees. Only its human reviewer credential was supplied to the browser; the agent credential remained in the harness process. No real personal documents were used.

The initial Playwright CDN download returned a 195-byte HTML unavailable page instead of a ZIP. The matching official Chrome-for-Testing archive was retrieved from `https://storage.googleapis.com/chrome-for-testing-public/158.0.8127.18/linux64/chrome-headless-shell-linux64.zip`, extracted outside the repo into Playwright's matching browser directory, and successfully launched at the expected version. No repository browser configuration was changed.

The connected harness confirmed:

- Exact human-approved append succeeds once; replay with original key returns the same result.
- A competing proposal becomes stale; approval returns 409 and creates no decision/grant.
- Refresh displays current state; the stale proposal cannot be approved.
- Revocation blocks a later execution attempt with 403.
- Document content/version remain exactly the expected single append.
- Evidence has one successful execution event and the revoked-denial event.
- Database has one consumed grant, two total grants; final snapshot contains one document and two attempts.

The authority/frontend subprocesses exited; PostgreSQL was stopped cleanly after its final snapshot. Its task-owned data directory was retained rather than destroyed after evidence generation.

An early HTTP-boundary invocation before the new worktree had a production build did not yield a completed result; it is excluded from passing evidence. The explicitly rerun post-build HTTP suite passed. Some initial audit invocations waited on network; the completed audit above used explicit network timeouts. These are not silently counted as successful checks.
